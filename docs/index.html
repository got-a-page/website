Getting started

Everything happens in the claim repo. One JSON file in pages/ is one page. The fastest path is the guided form, which writes the file for you. Names are 2-40 characters of lowercase letters, numbers and hyphens, and each GitHub account can claim up to 2 pages while we're young.

Instant mode - we host your page

For people without a website. You describe your page, we render it at name.got-a.page - responsive, accessible, light and dark, in one of six themes: sunrise, lagoon, forest, plum, slate, ember.

{
  "mode": "instant",
  "owner": { "github": "yourusername" },
  "showcase": true,
  "page": {
    "type": "person",
    "title": "Your Name",
    "tagline": "What you're about",
    "avatar": "https://github.com/yourusername.png",
    "theme": "sunrise",
    "links": [{ "label": "GitHub", "url": "https://github.com/yourusername" }],
    "sections": [{ "heading": "About", "text": "A few sentences about you." }]
  }
}
  • type: person or product today; project, community and event templates arrive in Phase 2.
  • showcase: true opts you into the Wall of Pages gallery (coming in Phase 2).
  • Product pages can add product.launchDate, a product.cta button, product.features and product.screenshots.
  • All URLs must start with https:// - the .page domain demands it.

Point mode - bring your own hosting

Already have a site? Point your name at it. Supported records: CNAME, A, AAAA, TXT. A CNAME can't be combined with other record types - that's a DNS rule, not ours.

{
  "mode": "point",
  "owner": { "github": "yourusername" },
  "purpose": "My portfolio",
  "records": { "CNAME": "yourusername.github.io" }
}

A merged claim creates DNS records. It does not add the domain to your hosting account. Both sides must be set up before your site can load at yourname.got-a.page. Instant mode needs none of these steps.

Connect your host before merge (point mode)

Add yourname.got-a.page to the host serving your site, using the steps below. Do this before the claim is merged and DNS is published, so the hostname is associated with your site first. Copy the host's recommended DNS target into your claim's records field. If you already opened the PR, edit the same file on your fork's branch to update it.

You do not need access to the got-a.page DNS dashboard or to change its nameservers. The claim repo publishes the supported records for you.

GitHub Pages

  1. Open your website's repository, not the claim repo. Go to Settings > Pages > Custom domain, enter yourname.got-a.page, then Save.
  2. If you publish from a branch, GitHub adds a CNAME file to the root of your publishing source. It contains only yourname.got-a.page, without https:// or a path. Keep it in future builds. If you use a custom GitHub Actions publishing workflow, the Pages setting is still required, but a CNAME file is ignored and is not required.
  3. In your claim JSON, use "records": { "CNAME": "yourusername.github.io" } (or your organization's github.io hostname). Do not include a repository path or https://.
  4. After merge and DNS sync, wait for GitHub's DNS check and certificate, then select Enforce HTTPS when available. GitHub says this can take up to 24 hours.

GitHub Pages instructions

Vercel

  1. Open your project, then Settings > Domains > Add Domain. Add yourname.got-a.page to that project.
  2. Copy the CNAME target recommended for this domain into your claim's records.CNAME. Vercel uses project-specific targets, so do not copy a generic target or another project's value.
  3. After merge and DNS sync, check the domain's configuration and certificate status in Vercel. No CNAME file is needed in your source repository.

Vercel instructions

Netlify

  1. Open your site's Domain management. Choose Add domain > Add a domain you already own, enter yourname.got-a.page, and follow Verify > Add domain. Keep external DNS; do not move the got-a.page nameservers.
  2. Under Production domains, use Pending DNS verification to see the recommended target. Usually it is your-site.netlify.app; copy the value Netlify gives you into records.CNAME.
  3. After merge and DNS sync, check DNS verification and HTTPS status in Netlify. No CNAME file is needed in your source repository.

Netlify domain steps and external DNS instructions

Cloudflare Pages

  1. Open Workers & Pages > your Pages project > Custom domains > Set up a domain. Enter yourname.got-a.page and continue through the setup.
  2. Associate the domain with your Pages project before the claim's CNAME is published. A CNAME alone, without this dashboard setup, can return a 522 error.
  3. Put the project's your-site.pages.dev target in records.CNAME. The claim repo handles DNS; you do not need to add the got-a.page zone to your account or change its nameservers.
  4. After merge and DNS sync, check that the custom domain is active and HTTPS works. No CNAME file is needed in your source repository.

After your PR merges

  1. Wait for the claim repo's DNS sync, then for DNS caches to update. Merge does not mean DNS or your host's certificate is ready immediately.
  2. Return to your host's custom-domain page. Resolve any verification warning and wait for its HTTPS certificate. DNS propagation and certificate issuance can take a while; GitHub documents up to 24 hours for Enforce HTTPS to become available.
  3. Visit https://yourname.got-a.page and confirm it shows your own site with a valid certificate. .page addresses require HTTPS, so an unfinished certificate can prevent the site from opening.
  4. Optional: if got-a.page was useful to you, star the claim repo on GitHub - it shows support and helps others find the project.

"Is it broken?" - troubleshooting

  • A browser certificate or privacy error right after merge (point mode): normal - your host's certificate is not ready yet. Wait, then enable Enforce HTTPS when your host offers it.
  • Your old yourname.github.io address shows the same error: expected. GitHub Pages redirects the old address to your custom domain as soon as you save it, so both show the certificate error during the waiting window, and both recover when the certificate is issued.
  • Your address says "unclaimed" (instant mode): the index has not republished yet. Give it a few minutes after merge and hard-refresh.
  • The page loads but looks unstyled: your site is probably loading its CSS or JS from the old address or over http://. Use relative asset URLs or update your static site generator's URL/base-path setting for the new domain.
  • Still stuck after a day? Open an issue with your page name and what you see - real humans read them.

If a host asks for an extra verification record, copy the exact record name, type and value into an issue for maintainers to review. Do not add it at the wrong name or combine a CNAME with TXT on the same hostname. The current claim format does not support arbitrary verification-record names. Never post passwords, API keys or login codes.

Before removing your custom domain or deleting your hosted site, remove the point-mode claim's DNS through a PR too. Leaving DNS pointed at a detached hosting account can let someone else claim that hostname.

HTTPS and the .page domain

Every .page address is forced onto HTTPS by browsers themselves (the TLD is on the HSTS preload list). That's great for safety, and it means two practical things: instant pages are always secure (we handle it), and point-mode targets must serve valid HTTPS or browsers will refuse to load them. All the hosts in the table above do this automatically once the custom domain is added.

The rules

  • Claim with your own GitHub account; owner.github must match the PR author.
  • Only you (or a maintainer) can edit or remove your page.
  • Everything in the repo is public, forever. No private data in your file.
  • No phishing, scams, malware, impersonation, illegal or adult content - see Terms.
  • Some names are reserved: service addresses, brand names, and words that would make this place worse.

Reporting abuse

See a page doing harm? Email abuse@got-a.page with the subdomain and what's wrong. Clear abuse comes down first and gets discussed after - the full policy is in ABUSE.md.

FAQ

  • I merged and my page doesn't load - is it broken? Almost certainly not. Check the troubleshooting list: point-mode pages wait on DNS and your host's certificate, and instant pages take a few minutes to publish.
  • Is it really free? Yes. The domain is paid for years ahead and everything else runs on free tiers. No ads. The site uses Google Analytics, which may collect usage data.
  • Do I need to star the repo? No. Star only if you genuinely like it.
  • Can I change my page later? Yes - edit your file with a new PR from the same GitHub account.
  • Can I move from instant to point mode? Yes - edit your file, change the mode, PR. Your content is always yours to take with you.
  • Can I get email on my subdomain? Not yet. MX records arrive in Phase 3 behind a careful feature flag.
  • Who runs this? Volunteers, in the open, on GitHub.
